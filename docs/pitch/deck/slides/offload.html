Where the pose AI runs

On the phone when it can. Offloaded when it can't.

On-device

iPhones that hold 12+ fps

A two-second benchmark on first launch decides. YOLOv8n-pose runs in Core ML on the Neural Engine.

Video stays on the phone. Works in airplane mode.

Cloud offload

Android, slower iPhones, or by choice

Frames stream over a WebSocket to the Spotter API, which relays them to our Hugging Face pose endpoint. Only joints come back.

Needs consent. Frames are processed in memory, never stored.

Fallbacks

Never a dead end

No consent: on-device if the phone can, else log sets by hand.

Cloud unreachable: on-device if it can, else pause quietly.

Logic lives in apps/mobile/src/pose/mode.ts. The phone never talks to Hugging Face directly. Before judging, confirm the cloud path is wired: cloudReachable is stubbed to false until the cloud pose work lands, so right now a phone that fails Core ML pauses. Same rep rules and silent cues run in both modes.
